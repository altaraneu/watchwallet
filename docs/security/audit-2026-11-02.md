# Independent code review of v1.0.0, 2026-11-02

Source: a two-part review by a separate Claude session, requested by the project owner. It reviewed
tag `v1.0.0` (commit `ab4a46a`) and commit `44739f6`. It read source code and did not run the app.
It is an AI code review, not a professional security audit. The original report is in Czech; this is
an English summary. It gave no overall "safe" verdict.

All items are planned for version 1.1. Status changes only with evidence from code or a test.

Status: `open`, `in progress`, `fixed` (commit or test named), `documented` (cannot be fully solved),
`owner` (needs the project owner).

## Reported as sound

The review found no signing or transaction-sending code, no author server, no analytics or dynamic
code loading in the reviewed code, and logs in debug builds only. Donation addresses appear only in
`DonationAddresses.kt` and match the README. Backup encryption is AES-256-GCM with PBKDF2-SHA256 at
600,000 iterations and random salt and IV. The chart library and `gradle-wrapper.jar` match official
files. Who owns the donation addresses cannot be shown from code.

## What the review did not cover

Transitive dependencies and the merged manifest, chain adapters line by line, price and portfolio
repositories, DataStore, the database, full settings and import screens, iOS code, tests, translations
and the Gradle distribution checksum. A follow-up review of the remaining code is in progress, and the
review will be repeated on the 1.1 tag.

## Limits that will remain

- Some secrets cannot be told apart from addresses by format, so the app cannot promise to catch all.
- Data providers must see the address they are asked about, plus the IP address unless a proxy is used.
